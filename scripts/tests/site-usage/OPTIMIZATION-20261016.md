# 站点观测：异步注册与复用优化

结论：已移除转发路径等待站点标签 fsync 的行为，并显著降低新连接元数据的分配与准备成本。持续传输仍有原子计数成本，不宣称零开销或公网吞吐提升。全局开关仍默认关闭，未部署。

## 实现边界

- 不可变反向 DNS 标签索引全进程共享，保持目录优先级和后缀边界，不缓存逐条访问域名。
- 同用户／站点复用上下行计数器；热缓存命中不加互斥锁、不分配。每条连接的两个延迟计数器内嵌在连接状态中。
- 仅首次分类注册异步：单工作线程、256 项队列、8192 对缓存及键长度上限。不复制载荷，不逐包创建任务。慢盘操作不持有主计费锁，快照不会等待站点注册锁。
- 排队前先记录持久化 pending 标记；注册完成后将内存前缀准确转入 mmap。注册失败和队列满标记受限，失败后通过后续连接触发至少间隔 5 秒的重试，复用原句柄。
- 正常退出最多排空 2 秒；异常退出可能丢失未注册完成的 RAM 观测，pending 标记使新版 Agent 明确报告不完整。必需计费不经过此异步路径。

## 新连接与分类

下表为三轮中位数及范围，单位 ns/op；开启采集。关闭时连接元数据仍为 0 次分配。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| P 单核连接元数据 | 498.8（495.6–502.9） | 220.8（220.6–222.5） |
| E 单核连接元数据 | 660.6（649.8–661.0） | 320.2（319.9–324.6） |
| 每连接堆分配 | 432 B / 13 次 | 208 B / 2 次 |
| P 单核 YouTube 分类 | 24.56（24.32–24.59） | 31.65（31.47–31.81） |
| P 单核 Apple 分类 | 738.3（730.9–740.9） | 34.86（34.81–34.93） |
| P 单核未命中分类 | 796.2（792.6–798.4） | 21.14（19.14–21.16） |

连接元数据准备约降低 56%（P）和 52%（E），堆分配次数减少约 85%。分类索引显著改善靠后和未命中规则，但目录首项 YouTube 的纯匹配慢约 7 ns；不能笼统称所有域名匹配都变快。整体连接准备仍明显降低。

## 持续计数：没有确定的提速结论

开启状态的三轮中位数及范围，单位 ns/op，前后均为 0 B / 0 次分配：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| P 单核 | 9.514（9.510–9.514） | 9.536（9.516–9.593） |
| E 单核 | 12.32（12.29–12.39） | 12.64（12.55–12.74） |
| P 四核热点 | 35.30（34.76–37.76） | 35.61（34.11–36.96） |
| E 四核热点 | 42.07（39.69–44.64） | 45.30（43.46–48.14） |

首轮 E 四核中位数约慢 7.7%，因此额外对 P/E 四核各做七轮交错计数补测，共 28 组，并[独立保留全部结果](results/20261016-optimization-counter-retest.json)，没有用补测覆盖首轮：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| P 四核热点 | 38.71（33.36–38.74） | 38.58（33.26–38.65） |
| E 四核热点 | 45.48（35.71–46.64） | 43.23（39.55–45.08） |

补测 E 四核方向反转，逐对变化从约 -11% 到 +26%；P 四核也存在波动。所有数据均展示，不能只取有利结果。逐核记录中补测 P 四核第 2 轮和 E 四核第 6 轮的未分配 E 核中位占用超过 10%，且未连续监测频率／温度；这些因素以及同用户缓存行竞争限制了细微差异的解释。持续计数没有被证明显著提速，也没有足够证据确认首轮 7.7% 是稳定回退。

关闭计数本身仍比开启便宜：本轮 P 单核约 4.96 vs 9.54 ns/op，E 单核约 5.67 vs 12.64 ns/op。这是一次计数调用的微基准，不是网络损耗百分比。本次主要收益是降低连接建立成本、消除可选磁盘注册对主路径的等待。

## 验证与未覆盖项

本轮实际通过：受影响 Go 五个包的 race 和 vet；慢盘不阻塞计费／快照、并发首次注册合并、队列／缓存／键长度上限、失败退避恢复、并发前缀转入、开关门控、退出排空／超时、共享 pending 标记；Agent 四个站点单元测试、严格 all-targets Clippy 和 Rust 格式检查；真实 Xray TCP／UDP、嗅探失败、路由排除域名与重启续接。复用脚本通过语法和格式检查，归档 JSON 可解析。

仍未覆盖：空闲主机的端到端优化前后吞吐、高连接率网络压力、最大用户规模和长期内存稳定性、各加密协议的容量。既有 [64 轮网络初测](RESULTS-20261016.md) 属于旧实现且主机有干扰，不冒充本次优化的网络验收。
